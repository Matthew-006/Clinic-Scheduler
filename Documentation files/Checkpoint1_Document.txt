=================================

Layered architecture:
  Main
   -> FileManager
    -> SimulationEngine
     -> Scheduler
      -> Data Structures
       -> Entities


Data Structures chosen for each list
------------------------------------

1) Events list -> LinkedQueue (Hassan)
   Why: events are already sorted by time in the input file.
         We only need first-in first-out (enqueue / dequeue).
   Main operations: enqueue O(1), dequeue O(1)

2) Waiting Emergency patients -> LinkedQueue (Hassan)
   Why: emergency patients are served in check-in order (FIFO).
   Main operations: enqueue O(1), dequeue O(1)
   removeById O(n) is used if a patient leaves.

3) Waiting Regular patients -> PriorityQueue (Matthew)
   Why: regular patients are not FIFO. Order depends on priority.
   Priority = (3 * checkInTime) + numTests (smaller first)
   Check-in time has weight 3 and tests have weight 1, so earlier
   patients are preferred, and fewer tests also helps.
   Main operations: enqueue O(n), dequeue O(1)

4) Branches and Doctors -> Array (Kerolos)
   Why: their counts are fixed after reading the file.
         No insert/delete during simulation, only access by index.
   Main operation: access O(1)

5) Done patients + all patients -> LinkedList (Mohamed)
   Why: done patients are only added at the end.
         allPatients is used to find a patient by id when reading
         Leave or Urgent events from the input file.
   Main operations: insertEnd O(1), findById O(n)

In-visit patients:
   No separate list. Each Doctor stores Patient* currentPatient
   because one doctor sees only one patient at a time.


File loading (Mohamed)
----------------------
FileManager reads the input file in order:
  B SU WU PS PJ
  doctors count per branch
  doctor data
  AutoE
  M events (C / L / U)

Each patient is created once with new, then shared by pointer
(no copying the same patient).
